Phase 1 — Browser Cache (0 ms if lucky)

1
Memory cache
Same browsing session & fresh? Return instantly — zero network.
2
Disk cache
Within Cache-Control: max-age? Serve from disk. Stale? Send a conditional GET: If-None-Match: "etag123" → server replies 304 Not Modified → reuse cached body (no transfer!).
3
Miss → full journey begins
All the headers that make this work: Cache-Control (freshness), ETag (fingerprint), Expires (legacy).
2

Phase 2 — DNS Resolution

Cache chain first: browser → OS → /etc/hosts → router forwarder (192.168.1.1:53) → recursive resolver (8.8.8.8) → hierarchy:

resolver → ROOT→"ask .com @ 192.5.6.30"→resolver → TLD→"ask ns1.example.com"→resolver → AUTH→93.184.216.34 · TTL 300
The DNS packet itself
UDP · src port 54321 (ephemeral) · dst port 53 · query type A — answer cached 300 s by every hop that touched it.
3

Phase 3 — ARP the Gateway

Routing decision: 93.184.216.34 ∉ 192.168.1.0/24 → use gateway 192.168.1.1 ARP cache: hit → router MAC 11:22:33:44:55:66 (miss → broadcast + reply) Frame built: DstMAC router · SrcMAC laptop · IP 192.168.1.5 → 93.184.216.34
The rule
MACs change every hop; IPs persist end-to-end (until NAT rewrites them in Phase 4!).
4

Phase 4 — TCP Handshake (+ NAT at the edge)

The handshake (to 93.184.216.34:443)
SYN (seq=x) → 1 RTT total ← SYN-ACK (seq=y, ack=x+1) ACK (ack=y+1) → ESTABLISHED
NAT happens right here
laptop: 192.168.1.5:52341 → 93.184.216.34:443 router: 203.0.113.5:10001 → 93.184.216.34:443 table: 10001 ↔ 192.168.1.5:52341
5

Phase 5 — TLS 1.3 Handshake (1-RTT)

The messages
ClientHello → TLS 1.3 · cipher suites · SNI: www.example.com · random ← ServerHello + Certificate (+chain) + Finished Client Finished →  ENCRYPTED CHANNEL ✓
  • SNI — which domain's cert to serve (many sites per IP)
  • Certificate — public key + domain, signed up a chain to a trusted root CA
  • Forward secrecy — fresh ephemeral DH keys per session; leak later ≠ decrypt past
  • 0-RTT — returning clients send data immediately (replay-risk caveat)
Diffie-Hellman — the paint analogy
public: YELLOW paint Alice secret RED · Bob secret BLUE 1 Alice: Y+RED=ORANGE → sends 2 Bob: Y+BLUE=GREEN → sends 3 Alice: GREEN+RED=BROWN Bob: ORANGE+BLUE=BROWN Same colour — secret never travelled! Eve saw Y, O, G — can't unmix.
A=g^a mod p · B=g^b mod p · shared = g^(ab) mod p
attacker can't compute g^(ab) from g^a, g^b — discrete logarithm problem
Why TLS needs TCP
TLS gives confidentiality & integrity, not delivery. It still leans on TCP for reliable, ordered record transport — that's why it runs after the handshake, inside the connection.

Phase 8 — The Ride Home & Phase 9 — Close

LB re-encrypts → TCP src 93.184.216.34:443 → dst 203.0.113.5:10001 Router NAT reverse: 10001 → 192.168.1.5:52341 → LAN delivery Laptop: TCP reassembles → TLS decrypts → HTTP parses → gunzip → RENDER 🎉 Sub-resources reuse the same TCP connection (keep-alive / HTTP-2 multiplexing) Close: FIN → ACK → FIN → ACK → client TIME_WAIT ~60 s → NAT entry expires

The full timeline (typical, ~100 ms RTT to server)

0–5 msBrowser + OS cache misses
conditional checks fail — we must go to the network.
5–70 msDNS resolution
resolver → root → TLD → authoritative → 93.184.216.34.
70–75 msARP + SYN out
gateway MAC cached; SYN leaves, NAT entry created.
75–177 msTCP handshake
SYN-ACK back, ACK out — ESTABLISHED (1 RTT).
180–283 msTLS 1.3
ClientHello → ServerHello+cert → Finished (1 RTT).
285–400 msRequest + server work
GET travels encrypted; LB, app, DB do their thing.
400–500 msResponse arrives
decrypt, decompress, render HTML; 600–800 ms → CSS/JS/images done (often via CDN).
Optimisations
Second visit ≈ 50 ms because cache + keep-alive + session resumption skip DNS, handshake and most transfer. That's the exam's "why is the second load faster" answer, phase by phase.

Lecture 13 — Rapid Revision Card (the whole course on one card)
9 phases: cache → DNS → ARP → TCP → TLS → HTTP → server → return → close.
Cache chain: memory → disk (+ETag/304) → OS → resolver.
DNS: resolver walks root→TLD→auth; TTL 300 caches it.
ARP: gateway MAC (cache or broadcast). MACs change per hop, IPs persist till NAT.
TCP = 1 RTT handshake; TLS 1.3 = 1 more RTT; both inside ~200 ms for 100 ms RTT.
DH: public g^a, g^b → shared g^(ab); secrets never transmitted; KDF → AES keys.
LB: SSL offload + X-Forwarded-For; NAT: port table both directions.
Second visit fast: cache hits + keep-alive + TLS resumption skip phases 1,2,4,5.
TTFB = request-out → first-byte-in (RTT + server time).
Close: FIN/ACK×2, TIME_WAIT, NAT entry expires.
