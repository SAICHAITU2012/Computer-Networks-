Why Computer Networks?

A computer network is a set of devices (called nodes) connected by communication channels (called links) that exchange data. That's the entire definition — everything else in this course is detail on top of it.

Nodes — the devices
Computers, laptops, phones, servers, printers, and the networking boxes themselves: routers, switches, hubs. Any device that can send, receive, or forward data.
Links — the connections
Wired (copper twisted pair, fiber optic) or wireless (Wi-Fi radio, cellular, satellite). A link carries signals that encode bits.

Why do we need them?

  • Communication — humans and programs talking across a room or across the planet (chat, email, calls, web).
  • Resource sharing — one printer for an office, one file server for a team, one database for a million users.
  • Scale — work distributed across machines: cloud computing, search engines, video streaming at planetary scale.
  • Cost & reliability — shared infrastructure and replicated systems beat every user owning everything.
Analogy
The classic mental model: the postal system. A letter (data) is placed in an envelope (packet) with an address (destination IP), handed to a post office (router), and forwarded office-by-office until it reaches the mailbox (destination device). No single postal worker knows the whole journey — each just knows the next office. This is exactly how Internet routing works (Lecture 7).
Big Picture
Everything you use daily — WhatsApp, UPI payments, YouTube, Instagram, exam results websites — is a program on one machine talking to programs on other machines through this stack of ideas. Master these 13 lectures and you can explain every step of what happens when you type a URL (Lecture 13 does exactly that).

Exam
A favourite short-answer: "Differentiate LAN and WAN." Key points: LAN = small area, privately owned, high speed, low latency; WAN = huge area, owned by telecom providers (leased links), moderate speed, higher latency and cost. Give one example of each.
Note
The Internet is not one WAN — it is millions of LANs and WANs interconnected: a network of networks. A VPN (Virtual Private Network) is a secure tunnel built on top of the Internet to make a remote machine behave as if it is on your LAN.

Internet Architecture — the Network of Networks

No single company owns the Internet. It grew by connecting smaller networks (ISPs) into a loose global hierarchy:

Figure 2. The Internet hierarchy: Tier-1 carriers form the core; regional and local ISPs bring access networks to your device.
  • Tier-1 ISPs own long-distance fiber backbones and peer with each other as equals — they never pay anyone for transit.
  • Tier-2 / regional ISPs buy connectivity from Tier-1s and sell to smaller networks.
  • Access networks (Tier-3) — local ISPs, mobile towers, campus networks — connect the last metres to your device.
  • Content providers (Google, Netflix, Cloudflare) run their own global networks and data centers, connecting into this hierarchy at many points (and via CDNs — Lecture 13).
Exam
"What is meant by the Internet being a network of networks?" — Answer shape: end systems connect into access ISPs (LAN, then ISP); access ISPs connect into regional ISPs; regional into Tier-1 backbone ISPs; smaller networks at each level are themselves networks of routers and links. Nobody owns the whole; interoperability comes from shared protocols (TCP/IP).

Network Edge vs Network Core

Figure 3. Edge devices reach the core through an access link; the core is a cooperating mesh of routers running packet switching.
Network Edge
End systems: PCs, phones, servers, IoT devices. Hosts = clients (requesters: your browser) and servers (responders: Google's machines). Edge devices run applications.
Network Core
A mesh of interconnected routers. Its only job: move data — millions of packets per second, from any edge to any other edge. Contains no applications; pure forwarding machinery.
Exam
"With a neat diagram, explain network edge and network core." Draw Figure 3. Edge = hosts + access networks (Wi-Fi, FTTH, DSL, cellular). Core = router mesh doing packet switching. One line each on client/server and on why the core is shared.

Circuit Switching vs Packet Switching

How does the core carry data for many conversations at once? Two historical answers:

Circuit Switching — the telephone way
Reserve a dedicated end-to-end path first ( signalling sets up the "circuit"), then send at fixed rate. Links are divided into channels by FDM (frequency-division: each call gets a frequency band) or TDM (time-division: each call gets repeating time slots).
  • Guaranteed constant rate & latency — perfect for voice.
  • Wasteful: silent moments (pauses in a call) still hold the circuit.
  • Setup time before any data; fails if any intermediate trunk is busy.
Packet Switching — the Internet way
No reservation. Data is chopped into packets (a few KB each) with headers; each router forwards them using store-and-forward: receive the whole packet, check it, send it on the next link. Packets from many users statistically share every link.
  • Efficient sharing — idle capacity is instantly reused.
  • Resilient: packets simply reroute around failures.
  • No guarantees — congestion causes queueing delay and loss.
Figure 4. Circuit switching reserves a fixed channel end-to-end; packet switching forwards self-contained packets over shared links.

Numerical: why packets win on efficiency

Users share a 1 Mbps link. Each user is active 10% of the time and needs 100 kbps when active.
Circuit switching: each user must reserve 100 kbps forever → only 1 Mbps ÷ 100 kbps = 10 users, and the link sits 90% idle for each of them.
Packet switching (n users): each user active with p = 0.1. Probability that more than 10 are active simultaneously: P(>10 active) = Σ k=11..n C(n,k) (0.1)k(0.9)n−k. For n = 35, this is under 0.04% — so packet switching supports ~35 users on the same link with essentially no congestion.
Total store-and-forward delay over N links = N × (L / R)
L = packet size in bits · R = link rate in bps — each link must fully receive the packet before retransmitting it
Numerical
Classic exam numerical: Send a 1,000-bit packet over two 1 Mbps links (store-and-forward). Total time = 2 × (1000 / 10⁶) = 2 ms. (First link: 1 ms to push it out; second router waits until it has all 1000 bits, then 1 ms more.) With a single 1 Mbps link it would be just 1 ms — each extra hop adds L/R.
Why the Internet chose packets
Data traffic is bursty (long silences, sudden bursts). Reserving capacity for the silence wastes it; statistical sharing exploits it. Result: cheaper, scalable, resilient — at the cost of congestion management, which TCP handles later (Lecture 10).

Delay & Latency — the Four Delays

Every packet suffers delays at every router hop. Total nodal delay has exactly four components:

Figure 5. The delay pipeline every packet passes through at each hop.
DelayWhat happensFormulaDepends onTypical size
ProcessingRouter examines header, checks bit errors, looks up output linkd_procRouter hardware speedMicroseconds — usually ignored
QueueingPacket waits in the output buffer while earlier packets are sentd_queueTraffic intensity (how busy the link is)0 when idle → grows unboundedly near congestion
TransmissionAll L bits of the packet are pushed onto the wired_trans = L / RPacket length L, link rate Rms scale for big packets on slow links
PropagationThe signal physically travels the medium's lengthd_prop = d / sDistance d, propagation speed s ≈ 2×10⁸ m/s (fiber/copper)~5 ms per 1000 km — physics, can't be upgraded!
Trap
Transmission ≠ Propagation. Transmission is writing bits onto the link (rate-limited by bandwidth); propagation is the signal racing along the wire (limited by physics). A 10-lane highway on-ramp analogy: transmission = how fast cars enter (one per second); propagation = how fast a car drives to the next city.

Worked example — compute all four delays

Given: packet length L = 1000 bytes, link rate R = 10 Mbps, link length d = 1000 km, propagation speed s = 2 × 10⁸ m/s, queueing delay ≈ 0 (link idle), processing ≈ 0.
1
Convert units first
L = 1000 B × 8 = 8000 bits; R = 10 Mbps = 10⁷ bps; d = 1000 km = 10⁶ m
2
Transmission delay
d_trans = L/R = 8000 / 10⁷ = 8×10⁻⁴ s = 0.8 ms
3
Propagation delay
d_prop = d/s = 10⁶ / (2×10⁸) = 5×10⁻³ s = 5 ms
4
Total nodal delay
d_nodal ≈ 0 + 0 + 0.8 + 5 = 5.8 ms — here propagation dominates

Queueing delay & traffic intensity

Traffic intensity ρ = (a · L) / R
a = average packet arrival rate (packets/s) · L = average packet size · R = link rate
Traffic intensity ρWhat happens to average queueing delay
ρ ≪ 1Arrivals are rare — packets rarely wait; average queueing delay ≈ 0
ρ → 1Delay grows rapidly and fluctuates wildly (bursts collide)
ρ > 1Arrivals exceed service rate — queue grows without bound → packets are dropped (loss)
Numerical
Practice: a = 1000 packets/s, L = 1000 bits, R = 2 Mbps → ρ = (1000×1000)/(2×10⁶) = 0.5: stable, moderate queueing. If a doubles to 2000 → ρ = 1: queue explodes. Design rule: keep ρ well below 1.

Latency vs RTT

  • Latency (one-way) = time for a packet to travel source → destination (all four delays summed over every hop).
  • RTT (Round-Trip Time) = there and back. Ping reports RTT (Lecture 12). Bengaluru → US server ≈ 200–250 ms RTT.
  • Latency matters as much as bandwidth for interactive apps: gaming, video calls, web page loads.

Bandwidth, Throughput & Bottlenecks

Bandwidth
The maximum rate a link can carry (bits/second). What your ISP advertises: "100 Mbps plan". Also called link capacity or rate R.
Throughput
The actual rate achieved end-to-end at an instant: bits/second successfully delivered. What your download bar shows.
Bottleneck link
The slowest link on the path — it alone caps the throughput. Fixing any other link changes nothing!
End-to-end throughput ≈ min(R₁, R₂, R₃, … Rₙ)
the path is a chain of links — water can't flow faster than the narrowest pipe
Figure 6. Bottleneck principle — upgrading R₁ (or your Wi-Fi) is pointless until the 2 Mbps link is fixed.
Analogy
A highway chain: 8-lane expressway (high bandwidth) feeding a single-lane village road (low bandwidth). Traffic arrives at the village rate no matter how wide the expressway is. Same with your 1 Gbps laptop NIC on a 20 Mbps broadband line.
Numerical
Path: server–R₁=30 Mbps → router –R₂=10 Mbps → ISP –R₃=50 Mbps → home. Throughput = min(30,10,50) = 10 Mbps. If ten clients share R₂ simultaneously and fairly, each gets ≈ 1 Mbps. Also note: delay and throughput interact — a 1 MB file's transfer time is roughly max(L/R_total, RTT-limited window growth) — revisited in Lecture 10 (sliding window).

Network Devices — Hub, Switch, Router, Modem

Hub
Layer 1 · Physical
Dumb repeater: copies bits from one port to every other port. All devices share one collision domain and one bandwidth pool. Obsolete — but a favourite exam contrast.
Switch
Layer 2 · Data Link
Learns which MAC address lives on which port and forwards frames only to the right port. Each port gets full bandwidth; connects devices within one LAN.
Router
Layer 3 · Network
Connects different networks; forwards packets using IP addresses and a routing table. The only device that lives in the network core. Your "home router" is router + switch + more (Lecture 11).
Modem
Edge · Modulator
MOdulator-DEModulator: converts between your home's digital signals and your ISP's line format (DSL phone line, cable TV coax, fiber light). The bridge onto the Internet.

Analogy
Hub = shouting in a room — everyone hears, only the addressee listens (chaos as crowd grows). Switch = an office receptionist who memorises faces (MACs) and hands each letter directly. Router = the postal system routing between cities (networks). Modem = the translator between your home's language and the ISP line's language.

OSI vs TCP/IP — a Bird's-Eye View

Complex systems need layering: each layer does one job, serves the layer above, and uses the layer below. Two models organise the ideas — OSI (7 layers, the vocabulary) and TCP/IP (4 layers, what the Internet actually runs). Full detail arrives in Lecture 2; today, meet the shape:

"Please Do Not Throw Sausage Pizza Away" → Physical, Data Link, Network, Transport, Session, Presentation, Application. (Top-down: "All People Seem To Need Data Processing".)

6Presentationformat, encryption — TLS lives here

TCP/IP model — 4 layers (DARPA) — what the Internet runs
Figure 7. Same ideas, different groupings: engineers implement TCP/IP but describe problems with OSI layer numbers ("that's a Layer 3 issue").
Exam
"Compare OSI and TCP/IP models." Points: OSI = 7 layers, theoretical reference, created by ISO for standardisation; TCP/IP = 4 (or 5) layers, practical, developed by DARPA, what the Internet actually uses. OSI's Session+Presentation collapse into TCP/IP's Application; OSI's Physical+Data Link collapse into Network Access. We implement TCP/IP but speak in OSI layer numbers.

Answer Key
A1. c — propagation = distance ÷ speed of the medium.
A2. b — 1500 B = 12,000 bits ÷ 3×10⁶ = 4 ms.
A3. c — switch (L2, MAC table); hub floods, router uses IP.
A4. b — receive fully, then forward (adds L/R per hop).
A5. c — throughput = min link = 4 Mbps.
A6. Nodes = communicating devices; links = transmission media. Reasons: communication, resource sharing (any two: cost, reliability, scale).
A7. LAN: building/campus, privately owned, 100 Mbps–10 Gbps, very low latency (home Wi-Fi). WAN: country/world, telecom-owned leased links, higher latency & cost (Internet backbone, bank ATM network).
A8. Millions of interconnected networks; each access LAN → local ISP → regional → Tier-1; no single owner; common protocols bind them. (Sketch as in Figure 2.)
A9. Bandwidth = capacity of a link; throughput = achieved end-to-end rate = min of links; bottleneck = the slowest link. Example: 100 Mbps Wi-Fi → 10 Mbps broadband = 10 Mbps.
A10. Transmission = L/R (push bits on, upgradeable by buying bandwidth); propagation = d/s (physics of distance, not upgradeable).
A11. Please Do Not Throw Sausage Pizza Away. 5+6+7 → Application; 4 → Transport; 3 → Internet; 1+2 → Network Access.
