Why IP Addresses?

MAC addresses (Lecture 2) only work locally — within one network segment. To route data across the Internet, across thousands of networks, we need a global addressing system. IP addresses provide:

Global uniqueness
Every public IP is unique world-wide — assigned by registries (IANA → regional registries → ISPs).
Hierarchy
The network portion enables routers to aggregate millions of destinations into few routing entries.
Logical & flexible
Reassignable in software — unlike the hardware-burned MAC.
Analogy
MAC = your name (travels with you, meaningless for postal delivery). IP = your postal address (hierarchical: city → street → house — exactly how routers narrow the search). A person can move houses (new IP) keeping the same name (MAC).

Subnet Mask & the AND Operation

A subnet mask is a 32-bit number: 1s mark network bits, 0s mark host bits — and the 1s are always contiguous from the left.

Mask 255.255.255.0 in binary: 11111111.11111111.11111111.00000000 └──────── 24 network bits ────────┘└ 8 host bits ┘

The one calculation everything else builds on

Network Address = IP address AND Subnet Mask
AND: 1 AND 1 = 1 · anything AND 0 = 0 — the mask "keeps" the network part and zeroes the host part
IP: 192.168.1.5 → 11000000.10101000.00000001.00000101 Mask: 255.255.255.0 → 11111111.11111111.11111111.00000000 AND ────────────────────────┴────────┴────────┴──────── 11000000.10101000.00000001.00000000 = 192.168.1.0 Network address = 192.168.1.0 ← same for every device in this subnet!

The four special addresses of every subnet

AddressHost bitsPurpose
Network addressall 0sIdentifies the subnet itself — not assignable
First host0…01First usable device (often the gateway)
Last host1…10Last usable device
Broadcast addressall 1sDelivers to ALL devices in the subnet — not assignable
Example — 192.168.1.0/24 Network: 192.168.1.0 First host: 192.168.1.1 Last host:192.168.1.254 Broadcast: 192.168.1.255
Total addresses = 2^(32 − N)  ·  Usable hosts = 2^(32 − N) − 2
N = prefix length · the −2 removes network + broadcast addresses

CIDR Notation

CIDR (Classless Inter-Domain Routing) writes the prefix as /N — the number of leading 1-bits — instead of a full mask.

Private rangeCIDRSizeTypical use
10.0.0.0 – 10.255.255.25510.0.0.0/816.7 MLarge corps, cloud VPCs

  • Private = not routable on the Internet — freely reusable inside any organisation; millions of homes all use 192.168.x.x.
  • Public = everything else — globally routable, assigned by ISPs/registries. Only your router's WAN side holds one (NAT, Lecture 11).
Trap
172.20.5.1 is private (172.16–31 range) but 172.32.0.1 is public! The /12 range stops at 172.31.255.255. Examiners love this.

Worked Examples (Exam Pattern)

Example 1 — analyse 192.168.10.130/25
/25 mask = 11111111.11111111.11111111.10000000 = 255.255.255.128 Last octet: 130 = 10000010 → first bit (network) = 1 → belongs to upper half Network: 192.168.10.128 Broadcast: 192.168.10.255 Hosts: 192.168.10.129 – 192.168.10.254 Usable: 2⁷−2 = 126
Example 2 — is 172.20.5.1 private?
172.20.x.x falls in 172.16.0.0 – 172.31.255.255 → YES, private (172.16.0.0/12)
Example 3 — network address of 10.45.60.100/20
/20 mask = 255.255.240.0 → third octet has 4 network bits + 4 host bits 60 = 00111100 → keep first 4 bits (0011), zero the rest → 00110000 = 48 Network: 10.45.48.0 Broadcast: 10.45.63.255 Usable: 2¹²−2 = 4094
Speed tip
For /20 in the third octet: block size = 256−240 = 16 → network octets are 0,16,32,48,64… 60 sits in 48–63 → network .48, broadcast .63. This "block-size jump" trick solves any subnet question in seconds.

IPv4 = 32 bits, 4 octets 0–255; space = 2³² ≈ 4.3 B.
Binary positions: 128 64 32 16 8 4 2 1 — add/subtract to convert.
Subnet mask: 1s = network, 0s = host, contiguous left.
Network = IP AND mask; broadcast = host bits all 1; usable = 2^(host bits) − 2.
CIDR /N: N network bits; /24→.0, /25→.128, /26→.192, /27→.224, /28→.240, /30→.252.
Classes: A 1–126 (/8) · B 128–191 (/16) · C 192–223 (/24).
Private: 10/8 · 172.16–31/12 · 192.168/16 — never Internet-routable.
Loopback 127.0.0.1 = self · 169.254.x.x = DHCP failed · 0.0.0.0 = any.

Answer Key
A1. c — 10.x.x.x is private; 172.32 is outside 172.16–31; 192.169 is outside 192.168.
A2. b — 2⁴−2 = 14.
A3. b — /26 blocks: 0, 64, 128, 192 → 77 sits in 64–127.
A4. b — APIPA self-assignment when DHCP fails.
A5. c — 240 = 11110000 → 28 ones.
A6. 172 = 128+32+8+4 = 10101100.
A7. Mask /16 keeps first two octets → 10.20.0.0.
A8. Network = the subnet's own identity (routers use it); broadcast = "all hosts here". Both are conventions every host must agree on — assigning them breaks addressing.
A9. Public = globally routable, registry-assigned, unique. Private = reusable internally, not routed on Internet. They exist because 4.3B addresses < devices on Earth — reuse + NAT (L11) stretches IPv4.
A10. 127.0.0.1 — packets never leave the machine. Uses: test the TCP/IP stack; run local dev servers (localhost:3000).
A11. /20 → mask 255.255.240.0; third octet 90 = 01011010 → keep 0101 → 01010000 = 80. Network 172.16.80.0, broadcast 172.16.95.255, hosts .80.1–.95.254, usable 4094.
A12. Use Figures 1 & 3; AND zeroes host bits because "anything AND 0 = 0" — leaving exactly the network identity all subnet devices share.
A13. 11000000.10101000.00000001.00000101 AND 11111111.11111111.11111111.00000000 → network 192.168.1.0, broadcast 192.168.1.255.
A14. The /12 private block is 172.16.0.0–172.31.255.255 — 172.25.x.x lies inside it, so it IS private. Private ≠ only 10/8 & 192.168/16.
Wrap-Up — carry these into Lecture 4
Anatomy
32 bits = 4 octets; the mask draws the line between network bits (shared identity) and host bits (who you are inside it).
AND to find home
IP AND mask = network address. "Anything AND 0 = 0" zeroes host bits, leaving exactly the subnet's identity.
Special addresses
All-host-bits-0 = network, all-ones = broadcast — never assign them. 127.0.0.1 talks to yourself.
Private blocks
10/8, 172.16/12, 192.168/16 are reusable inside networks; public addresses are globally unique. NAT (L11) bridges the two.
