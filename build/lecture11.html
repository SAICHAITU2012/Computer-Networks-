ARP — Address Resolution Protocol

The gap: IP routes globally, Ethernet delivers locally by MAC. ARP bridges them: "which MAC owns this IP on my LAN?"

Figure 1. One broadcast question, one unicast answer, one cached mapping.
arp commandsterminal
arp -a # view cache (all OSes) ip neigh show # Linux preferred — shows STATE too ip neigh flush all # clear cache (root)
StateMeaningStateMeaning
REACHABLEconfirmed recently (~30 s)PROBEsending unicast re-checks
STALEunused; verify before next useFAILEDno answer → entry deleted
DELAYturned stale; probe pending—
Gratuitous ARP
A device ARPs for its own IP: (1) conflict detection — a reply means someone stole my IP! (2) cache refresh — announce a new/failovered MAC to everyone.
Proxy ARP
A router answers ARP on behalf of devices on other subnets — legacy trick to make distant hosts look local.

NAT / PAT — the Translation Table

Setup: LAN 192.168.1.0/24, router WAN IP 203.0.113.5. The router keeps a live table mapping every conversation:

Outbound — SNAT
laptop sends: 192.168.1.5:52341 → 142.250.195.46:80 router rewrites src: 203.0.113.5:10001 (+ creates entry)
Inbound reply — reverse lookup
google replies: → 203.0.113.5:10001 table: 10001 → 192.168.1.5:52341 → delivers to laptop ✓
Key
The port is the discriminator. Three devices share one public IP because each owns a distinct translated port. No table entry = drop — that's why NAT is an "accidental firewall" against unsolicited inbound traffic.
Port forwarding — DNAT
Static rule: public 27015 → 192.168.1.10:27015. Friends connect to your public IP:27015 and land on the game server. Uses: game/web servers, cameras, SSH-at-home.
NAT traversal (P2P)
STUN: a server tells you your public IP:port → try direct. TURN: relay everything when STUN fails. ICE: tries STUN then TURN — how WebRTC video calls punch through NAT.

DHCP — the DORA Dance

DHCP hands a joining device everything it needs: IP, subnet mask, default gateway, DNS server, lease time. It runs over UDP 67 (server) / 68 (client) — UDP because the client has no IP yet and needs broadcast (TCP can do neither).

Figure 2. DORA — Discover, Offer, Request, Acknowledge. REQUEST stays broadcast on purpose (declining other servers).

Lease renewal timeline

TimeEvent
T1 = 50% of leaseclient unicasts REQUEST to the original server ("renew me")
T2 = 87.5%no answer? broadcast REQUEST — any DHCP server may extend
T3 = 100%lease expires — IP lost; full DORA restarts (brief outage)
24-hour lease example
T1 at 12 h (unicast renew) → T2 at 21 h (broadcast) → T3 at 24 h (expire + re-DORA). Large networks with many subnets use DHCP relay agents on routers to forward broadcasts to a central server.

Lecture 11 — Rapid Revision Card
ARP: broadcast "who has IP X?" → unicast "X is at MAC" → cache. States: REACHABLE→STALE→DELAY→PROBE→FAILED.
Gratuitous ARP: self-ARP = conflict check + cache refresh. Proxy ARP = router answers for others.
NAT table: (priv IP:port ↔ pub IP:port); port = discriminator; no entry → drop (accidental firewall).
Port forwarding = DNAT: fixed public port → private host:port. Traversal: STUN → TURN, chosen by ICE.
DORA: Discover(bcast) → Offer → Request(bcast!) → Ack. UDP 67 server / 68 client.
Lease: T1 50% unicast renew · T2 87.5% broadcast · T3 100% expire → re-DORA.
Home router = router + DHCP + DNS fwd + switch + AP (+firewall).
Boot/join order: router WAN-DHCP → serve LAN; laptop: Wi-Fi → DORA → gARP → ARP GW → online.
