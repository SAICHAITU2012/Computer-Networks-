Subnetting Drill (do all 10, then check)

The problems
  1. 10.20.30.40/16 → network? broadcast?
  2. 192.168.1.77/26 → network? usable range?
  3. 172.16.90.77/20 → mask? network? usable count?
  4. Need 50 hosts → prefix? usable?
  5. Need 500 subnets from /16 → new prefix? hosts each?
  6. How many /28s in a /24?
  7. 172.25.10.5 — public or private?
  8. 172.32.10.5 — public or private?
  9. 192.168.10.130/25 → network? broadcast?
  10. 10.45.60.100/20 → network? broadcast?
Answers
  1. 10.20.0.0 · 10.20.255.255
  2. 192.168.1.64 · .65–.126 (bc .127)
  3. 255.255.240.0 · 172.16.80.0 · 4094
  4. /26 · 62
  5. /25 · 126 each (2⁹=512 subnets)
  6. 16
  7. Private (172.16–31)
  8. Public — outside /12!
  9. 192.168.10.128 · .255
  10. 10.45.48.0 · 10.45.63.255
The 30-second method — worked on drill #3 (172.16.90.77/20)
  1. Block size from the octet that changes: /20 → third octet keeps 4 prefix bits → block = 2⁸⁻⁴ = 16 → boundaries 0, 16, 32, 48, 64, 80, 96…
  2. Network: largest boundary ≤ 90 → third octet 80 → 172.16.80.0.
  3. Broadcast: next boundary − 1 → 96 − 1 → 172.16.95.255.
  4. Usable: .80.1 – .95.254 → host bits = 12 → 2¹² − 2 = 4094.
Traps that cost marks
"Usable" excludes network + broadcast (−2, always). 172.32 is public (outside 16–31). /31 and /32 have no usable hosts. Count subnets with 2^borrowed, hosts with 2^remaining − 2 — don't mix them.
Sanity checks
Network + block ≤ next network. Broadcast = network + block − 1. First usable = network + 1. If your broadcast crosses the next boundary, your block size is wrong — recount the borrowed bits.

Mock Exam — Answer Key
MCQ: 1-c · 2-c · 3-b · 4-b · 5-b · 6-c · 7-c · 8-c · 9-b · 10-b
11. Segment (ports) → Packet (IPs) → Frame (MACs); headers added going down.
12. Reserved path vs store-and-forward · FDM/TDM vs statistical sharing · guaranteed vs queueing · wasteful vs efficient; Internet = bursty traffic → packets.
13. L2 frames are local-only — rebuilt per hop; IP is the end-to-end identity routers forward on; NAT rewrites at the edge only.
14. Never re-advertise a route out the interface it came from (silence); poison reverse advertises it as ∞ explicitly — the false "path through you" never exists, so the count never starts.
15. GET safe+idempotent · POST neither · PUT idempotent not safe · DELETE idempotent not safe.
16. Each flow owns a translated port: (priv IP:port ↔ pub IP:port); replies look up by port; no entry → drop (accidental firewall).
17. d_trans = 1.2 / 12 / 1.2 ms; d_prop = 3 / 0.15 / 6 ms; total = 23.55 ms (L=12000 bits).
18. Sales .0/25 (bc .127) · Tech .128/26 (bc .191) · Admin .192/27 (bc .223) · Guest .224/28 (bc .239) · WAN .240/30 (bc .243).
19. Order Delhi(0) → Hyderabad(2) → Bangalore(4) → Mumbai(5) → Chennai(8); Delhi→Chennai = Delhi→Hyd→Bang→Chen (8).
20. B sets C=∞; A's stale "C=2" arrives → B:3 → A:4 → … to 16; cures: split horizon, poison reverse, triggered updates, holddown.
21. browser → OS → hosts → resolver cache → root (referral .com) → TLD (referral ns1) → authoritative (A record, TTL) → cached & returned. Recursive for the client; iterative by the resolver.
22. SYN(x) → SYN-ACK(y, x+1) → ACK(y+1); close FIN(m)→ACK(m+1)→FIN(n)→ACK(n+1); TIME_WAIT 2×MSL for a lost final ACK + duplicate expiry.
23. cache(L7 app) → DNS(L7/UDP) → ARP(L2) → TCP(L4) → TLS(L6) → HTTP(L7) → LB/app → NAT+routing(L3) → close(L4). Any faithful ordering with layers = full marks.
