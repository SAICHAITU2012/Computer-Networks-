What is a Protocol? Why Layers?

A protocol is a set of agreed-upon rules governing communication. Both sender and receiver must follow the same protocol or communication fails. In networking a protocol defines three things:

Format
Which fields appear, in what order, what each byte means (the message "grammar").
Sequence
Who initiates, who responds, and in what order (the "conversation flow").
Actions
What to do on events: message lost, corrupted, arrives out of order.

Why layered protocols?

Rather than one massive protocol doing everything, networking uses a layered architecture: each layer has one job, relies on the layer below, and provides a service to the layer above.

  • Modularity — change one layer without touching others: Apple can update Safari's HTTP engine without modifying TCP.
  • Reusability — TCP works identically over Ethernet, Wi-Fi, or 4G.
  • Isolation — easier diagnosis: if TCP connects but the page is broken, the problem is in the application layer, not the network.
Analogy
Sending a gift: you (application) write the card; the packing service (transport) boxes it; the courier company (network) routes the box; the local delivery van (data link) carries it on the final street; the road (physical) carries the van. Each level only cares about its own wrapping.

The OSI Model — 7 Layers

In the 1980s vendors (IBM, DEC…) had incompatible systems. The ISO created the OSI (Open Systems Interconnection) model, 1984, as a universal reference. Every network function belongs to one of 7 layers:

7Applicationrules for what apps say — HTTP · SMTP · DNS · SSH
6Presentationformatting, compression, encryption — TLS · JPEG · gzip
5Sessionsession lifecycle — largely absorbed into apps/TCP today
4Transportend-to-end delivery, ports, reliability — TCP · UDP
3Networkrouting across networks, IP addressing — IP · ICMP
2Data Linklocal delivery, frames, MAC — Ethernet · Wi-Fi 802.11
1Physicalbits on the wire — voltages · light · radio (Cat6, 802.11)
Layer numbers are used from TOP (7) to BOTTOM (1) — data flows 7→1 on send, 1→7 on receive

How we use both
We implement TCP/IP protocols, but talk about them with OSI layer numbers — "that's a Layer 3 problem", "an L2 switch". This course does the same: study TCP/IP protocols, use OSI numbers as vocabulary.
Note
Some textbooks show TCP/IP as 5 layers (Application, Transport, Network, Data Link, Physical) — identical ideas, just with the Network Access layer split apart. Know both counts: 4 or 5.

Encapsulation & Decapsulation

Encapsulation (sender): going DOWN the stack, each layer adds its own header around the data from above. Decapsulation (receiver): going UP, each layer strips its header and passes the payload up.

Figure 2. Encapsulation wraps data in layer-headers going down; decapsulation unwraps it going up.
Why?
Why is the Ethernet destination the router, not Google? Ethernet only works on the local network. Your laptop doesn't know (and can't use) Google's MAC address — so L2 delivers to the router, which forwards the IP packet to the next hop and builds a brand-new Ethernet frame for that leg.

Headers, Payload & the Nesting Rule

HEADERcontrol information PAYLOADthe actual data being sent

Typical header contents: source & destination addresses (at that layer's scope), payload length, payload type/protocol, sequence numbers, error-check values, control flags (SYN, ACK…).

The nesting rule
Ethernet payload = IP packet  →  IP payload = TCP segment  →  TCP payload = HTTP message  →  HTTP payload = the webpage HTML

Ethernet Frame — Byte by Byte

8 BPreamble+SFD 6 BDest MAC 6 BSrc MAC 2 BEtherType 46–1500 BPayload (usually an IP packet) 4 BFCS
Min frame 64 B · Max frame 1518 BPreamble syncs the receiver's clock
Figure 4. Ethernet II frame layout.
  • Preamble (7 B) + SFD (1 B) — synchronise the receiver's clock; SFD marks "real data starts after me".
  • Destination MAC (6 B) — Unicast one device · FF:FF:FF:FF:FF:FF broadcast to all · multicast for groups.
  • Source MAC (6 B) — sender's hardware address.
  • EtherType (2 B) — what's inside the payload, so the receiver knows which upper protocol to hand it to.
  • Payload (46–1500 B) — smaller data is zero-padded up to 46 B (64-byte minimum enables collision detection on old shared Ethernet).
  • FCS (4 B) — CRC over the whole frame. Mismatch → frame silently discarded (no retransmit — recovery is TCP's job, L4).

MTU & IP Fragmentation

MTU — Maximum Transmission Unit: the largest payload a single frame can carry on a link.

Link typeMTULink typeMTU
Ethernet1500 bytesJumbo frames (data centre)up to 9000 B
Wi-Fi (in practice)1500 B (Ethernet-compatible)Loopback interface65536 B

If an IP packet exceeds a link's MTU, the IP layer fragments it. Example — 4500-byte payload over Ethernet (MTU 1500):

IP HdrFrag 1bytes 0–1479offset 0 · MF=1 IP HdrFrag 2bytes 1480–2959offset 185 · MF=1 IP HdrFrag 3bytes 2960–4439offset 370 · MF=1 IP HdrFrag 4bytes 4440–4499offset 555 · MF=0 (last)
Figure 5. One 4500-byte IP packet → four fragments (1480 bytes of data each + 20-byte header).
IP header fieldPurpose in fragmentation
IdentificationAll fragments of the same original packet share this 16-bit ID
Fragment OffsetWhere this fragment starts, in 8-byte units (13-bit field × 8 covers 65,528 B — enough for max IP size 65,535 B)
MF — More Fragments1 = more pieces coming · 0 = last fragment
DF — Don't Fragment1 = router must DROP (not fragment) if too large — used by PMTUD
Rules
Fragmentation can happen at any router whose MTU is smaller — but reassembly happens ONLY at the final destination. Lose even one fragment → destination discards all of them → source TCP retransmits the whole thing.

Path MTU Discovery (PMTUD) — how modern systems avoid fragmentation

1
Send with DF = 1
Packets marked "don't fragment".
2
Small-MTU router drops & reports
It returns ICMP "Fragmentation Needed, MTU = X".
3
Sender adjusts & retries
Repeats until the size fits the whole path — no fragments ever sent.
Gotcha
Firewalls that block all ICMP break PMTUD: large transfers (email attachments, image uploads) mysteriously hang while small ones succeed. Classic interview/troubleshooting trap.

Answer Key
A1. b — Data Link (L2) frames carry packets locally.
A2. c — 0x0806 = ARP (0x0800 = IPv4, 0x86DD = IPv6).
A3. c — ceil(4500/1480) = 4 fragments of ≤1480 data bytes.
A4. c — reassembly only at the final destination.
A5. b — MACs rewritten each hop; TTL decremented; IPs stay.
A6. Agreed rules: format, sequence, actions. Benefits: modularity, reusability, isolation (any three with one-line explanations).
A7. PDNTSPA; 5+6+7→Application, 4→Transport, 3→Internet, 1+2→Network Access.
A8. Figure 4 layout; FCS = CRC error check; mismatch → silent discard (TCP recovers later).
A9. Segment/TCP/ports/end-to-end · Packet/IP/IPs/host-to-host · Frame/Ethernet/MACs/one hop.
A10. Largest frame payload per link (1500 B Ethernet). 46-byte min → 64-byte min frame for collision detection on legacy shared Ethernet; smaller data is padded.
A11. 48-bit: 3-byte OUI (IEEE, manufacturer) + 3-byte device ID. Local scope only — each hop's frame is freshly built for that local leg; IPs provide the global end-to-end identity.
A13. 4 fragments: 0–1479 (off 0, MF1), 1480–2959 (off 185, MF1), 2960–4439 (off 370, MF1), 4440–4499 (off 555, MF0). Identification + offset + MF enable reassembly.
A12/A14/A15. Use Figures 2 & 5 and the PMTUD steps — graders award labelled diagrams and the "opaque payload" principle stated explicitly.
Wrap-Up — carry these into Lecture 3
Encapsulation
Every layer wraps the layer above: Data → Segment → Packet → Frame. Decapsulation reverses it at the receiver.
Two addresses
IPs identify hosts end-to-end and never change; MACs deliver on the local link and are rewritten at every hop.
MTU
1500 B Ethernet limit → packets larger than MTU−20 are fragmented; the receiver reassembles using ID + offset + MF.
Why layers win
TCP runs unchanged over Wi-Fi, Ethernet or 4G because each layer treats the one above as opaque payload.
