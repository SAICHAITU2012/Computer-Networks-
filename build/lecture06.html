Why Dijkstra Fails on Negative Edges

Dijkstra's greedy assumption: once a node is finalised (popped), its shortest distance is correct. Negative edges break exactly this.

Figure 1. The classic counterexample — greediness + negative edges = wrong answer.
2

Bellman-Ford — the Fix

Core idea: relax every edge, V−1 times. Each full pass propagates shortest paths at least one more hop further. Why V−1? Any shortest path (without a negative cycle) visits at most V−1 edges.

bellman-ford with negative-cycle detectionJAVA
// edges: (u, v, weight) — processing order doesn't matter! static Map<String, Integer> bellmanFord(List<Edge3> edges, Set<String> vertices, String src, Map<String, String> prev) { Map<String, Integer> dist = new HashMap<>(); for (String v : vertices) dist.put(v, Integer.MAX_VALUE); dist.put(src, 0); for (int i = 0; i < vertices.size() - 1; i++) { // V−1 passes for (Edge3 e : edges) if (dist.get(e.u()) != Integer.MAX_VALUE && dist.get(e.u()) + e.w() < dist.get(e.v())) { dist.put(e.v(), dist.get(e.u()) + e.w()); // relax prev.put(e.v(), e.u()); } } for (Edge3 e : edges) { // V-th pass = detector if (dist.get(e.u()) != Integer.MAX_VALUE && dist.get(e.u()) + e.w() < dist.get(e.v())) throw new IllegalStateException("Negative weight cycle detected!"); } return dist; }
bellman-ford with negative-cycle detectionC++
// edges: (u, v, weight) — processing order doesn't matter! map<string, int> bellmanFord(vector<Edge3>& edges, int V, string src, map<string, string>& prev) { map<string, int> dist; for (auto& [v, _] : dist) dist[v] = INT_MAX; dist[src] = 0; for (int i = 0; i < V - 1; ++i) { // V−1 passes for (auto& e : edges) if (dist[e.u] != INT_MAX && dist[e.u] + e.w < dist[e.v]) { dist[e.v] = dist[e.u] + e.w; // relax prev[e.v] = e.u; } } for (auto& e : edges) { // V-th pass = detector if (dist[e.u] != INT_MAX && dist[e.u] + e.w < dist[e.v]) throw runtime_error("Negative weight cycle detected!"); } return dist; }

Negative cycles = routing loops

Detected
If a V-th pass can still relax → a negative cycle exists (e.g. A→B(1)→C(−3)→A(1): each lap −1 → "shortest path" is meaningless). In networking, a negative cycle IS a routing loop — packets circulating forever. Bellman-Ford detects it; Dijkstra cannot.

Negative edges✗ fails✓ handles

Minimum Spanning Tree (MST)

Spanning tree
Connects all vertices, has no cycles, exactly V−1 edges.
Minimum spanning tree
The spanning tree with the lowest total edge weight.
Two classics
Kruskal: sort edges, add if no cycle (union-find). Prim: grow tree from any node, always add cheapest outgoing edge.
kruskal — sort + union-findJAVA
static List<Edge> kruskal(List<Edge> edges, Set<String> vertices) { edges.sort(Comparator.comparingInt(Edge::w)); // 1. sort by weight Map<String, String> parent = new HashMap<>(); vertices.forEach(v -> parent.put(v, v)); // 2. find with path compression (halving) ... find(String x) { while (!parent.get(x).equals(x)) { parent.put(x, parent.get(parent.get(x))); x = parent.get(x); } return x; } List<Edge> mst = new ArrayList<>(); for (Edge e : edges) { String ru = find(e.u()), rv = find(e.v()); if (!ru.equals(rv)) { // 3. different trees? merge (no cycle) parent.put(ru, rv); mst.add(e); } } return mst; // stops naturally at V−1 edges }
kruskal — sort + union-findC++
vector<Edge> kruskal(vector<Edge> edges, int V) { sort(edges.begin(), edges.end(), [](const Edge& a, const Edge& b) { return a.w < b.w; }); // 1. sort by weight vector<int> parent(V); iota(parent.begin(), parent.end(), 0); // 2. find with path compression (halving) function<int(int)> find = [&](int x) { while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; } return x; }; vector<Edge> mst; for (auto& e : edges) { int ru = find(e.u), rv = find(e.v); if (ru != rv) { // 3. different trees? merge (no cycle) parent[ru] = rv; mst.push_back(e); } } return mst; // stops naturally at V−1 edges }

MST in real networks — Spanning Tree Protocol (STP, IEEE 802.1D)

The problem
Ethernet switches with redundant links create loops — broadcast frames circulate forever (a "broadcast storm") and melt the LAN.
The fix
Switches run a distributed MST algorithm: redundant links are logically blocked, leaving a loop-free tree. If an active link fails, STP unblocks a spare — automatic failover.

Distance Vector vs Link State — the Big Split

Distance Vector (Bellman-Ford based)
  • Each router knows costs to direct neighbours only
  • Periodically broadcasts its entire routing table to neighbours
  • Update rule: dist[dest] = min(dist[dest], cost_to_nbr + nbr_dist[dest])
  • Converges over many rounds; partial (local) view
  • Protocols: RIP, BGP (path-vector)
Link State (Dijkstra based)
  • Each router floods its local link state (neighbours + costs) to ALL routers
  • Every router builds the complete topology map
  • Every router independently runs Dijkstra → consistent results
  • Fast convergence; no count-to-infinity
  • Protocols: OSPF, IS-IS

Exam
The one-liner that earns marks: "DV shares distances, LS shares topology." Everything else (convergence speed, loop behaviour, algorithms) follows from that single design difference.

How the Internet Stacks Its Routing

Figure 2. Inside each Autonomous System: OSPF/IS-IS. Between ASes: BGP. Your home router just points a default route at your ISP.
AS
An Autonomous System = a network under one administrative control with a unique ASN: Google AS15169, Cloudflare AS13335, Jio AS55836, BSNL AS9829. IGPs (RIP/OSPF/IS-IS) run inside; BGP (EGP) runs between.

Dijkstra breaks on negative edges — it finalises B(2) before seeing A→C→B = 1.
Bellman-Ford: relax all edges V−1 times; V-th pass still relaxes → negative cycle. O(V×E).
MST: spans all nodes, V−1 edges, no cycles, minimum weight. Kruskal = sort + union-find; Prim = grow.
City graph MST: Hyd–Bang 2, Del–Hyd 2, Mum–Hyd 3, Chen–Bang 4 → 11.
STP (802.1D): switches build a spanning tree, block redundant links → no broadcast storms; failover unblocks spares.
DV shares distances (table to neighbours, Bellman-Ford) → RIP; count-to-infinity risk.
LS shares topology (flood LSAs, everyone runs Dijkstra) → OSPF; fast, loop-free.
BGP = path-vector between ASes; inside AS = OSPF/IS-IS; home router = default route.

Wrap-Up — carry these into Lecture 7
Bellman-Ford
Relax every edge V−1 times → handles negative edges; a further pass that still improves = negative cycle. Dijkstra has no such safety net.
MST
Kruskal: sort edges, take the cheapest that doesn't form a cycle (union-find). Prim grows one tree. Both give the same total weight.
DV vs LS
DV = "tell your neighbours the whole map" (distance vectors). LS = "tell everyone your neighbourhood" (link-state floods).
Count to infinity
Bad news travels slowly in DV — that's why real networks moved to LS (OSPF) inside ASes and patched DV with path vectors (BGP) between them.
