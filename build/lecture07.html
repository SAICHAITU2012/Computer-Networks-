Routing vs Forwarding

ConceptDefinitionWhenPlaneSpeed
RoutingDeciding WHERE packets should go — building/maintaining the routing tablePeriodically / on topology changeControl planeSlow, intelligent (algorithms, protocols)
ForwardingActually moving each packet out the correct interfaceFor every single packetData planeFast, mechanical (table lookup, ASIC hardware)
Analogy
Routing = planning the highway map (surveying roads, updating the map). Forwarding = reading a signpost at each junction and turning. Drivers (packets) never see the map — only signposts.

What is a router?

  • Multiple network interfaces, each attached to a different network
  • A routing table: destination → next hop + interface
  • A routing engine (control plane) that learns routes
  • A forwarding engine (data plane) that processes packets at line speed
Figure 1. A router joins two or more networks — one interface per network.
Exam
Router vs Switch: Switch = Layer 2, forwards by MAC, inside one LAN. Router = Layer 3, forwards by IP + routing table, between networks. Modern "home routers" bundle both (Lecture 11).

Longest Prefix Match (LPM)

When a packet's destination matches multiple entries, the most specific (longest) prefix wins.

Worked lookup — destination 192.168.1.200
Table entryMatches?Bits matchedResult
192.168.0.0/16 via 10.0.0.1✓ (192.168.x.x ⊂ /16)16
192.168.1.0/24 via 10.0.0.2✓24
192.168.1.128/25 via 10.0.0.3✓ (.200 is in .128–.255)25★ WINNER
0.0.0.0/0 via 10.0.0.4✓ (matches everything)0
Decision: forward via 10.0.0.3 — 25 bits beat 24, 16 and 0.
Why LPM matters
It enables hierarchical routing: an ISP carries one route 10.0.0.0/8 for a million customers, while a customer with 10.45.0.0/16 gets the more specific (winning) route. Specific overrides general — that's also how BGP hijacks work (Lecture 8).

Default Route & Static Routing

Default route — 0.0.0.0/0
Matches every destination (zero bits checked). The fallback when nothing else matches: "if in doubt, send here".
Who needs a default?
Home device → home router → ISP → Tier-2 → Tier-1. But a Tier-1 core router has NO default — it carries the full Internet table (900K+ routes) because there is nobody "above" it to default to.
static routing commandsterminal
ip route add 192.168.20.0/24 via 10.0.0.1 # specific route ip route add default via 10.0.0.1 # default route ip route del 192.168.20.0/24 via 10.0.0.1 # remove ip route show # verify # floating static (backup): high metric = used only if better route dies ip route add 10.5.0.0/24 via 10.0.1.1 metric 200
Static routingAssessment
Good forSmall networks · stub networks (one way in/out) · security-critical fixed paths · default gateways
Fails at scaleManual → error-prone · no failover (dead next hop = black hole) · one entry per destination doesn't scale

Packet Forwarding — Hop by Hop

At EVERY router, for EVERY packet: 1. Extract destination IP 2. Search routing table — Longest Prefix Match 3. Match? → forward to next hop via that interface 4. No match & no default? → DROP + ICMP "Destination Unreachable"
Figure 2. The forwarding decision loop — millions of times per second.
Complete trace — Laptop 192.168.1.5 → Server 10.50.20.100
Laptop→R1→R2→R3→Server

Key idea
No router knows the full path. Each knows only the next hop — yet the chain of local decisions carries the packet across the planet. That's the "hop-by-hop" principle (and why routing loops are so dangerous — next lecture).

What changes at each hop?

Header fieldChanges?Why
IP Source / DestinationNo (unless NAT)End-to-end identity
TTLYes — −1 per routerPacket with TTL = 0 is dropped + ICMP Time Exceeded — prevents infinite loops
Ethernet Src/Dst MACYes — rewrittenNew frame per hop (L2 is local-only)
TTL & traceroute
TTL starts at 64 (Linux/mac) or 128 (Windows). traceroute exploits it: send TTL=1 → router 1 drops & complains (revealing itself); TTL=2 → router 2 complains; … until the destination answers. That's how Lecture 12 maps paths.
Lecture 7 — Rapid Revision Card
Routing = build the table (control, slow); forwarding = per-packet lookup (data, fast).
Routing table: dest prefix → next hop + interface (+ metric, source).
LPM: longest matching prefix wins — /25 beats /24 beats /16 beats /0.
Default 0.0.0.0/0 matches everything; Tier-1 cores have none (full table).
Static: ip route add NET via NEXT_HOP; simple, no failover; floating = backup metric.
Forwarding loop: dest IP → LPM → next hop → new frame; no match → drop + ICMP Unreachable.
Per hop: TTL−1, MACs rewritten, IPs unchanged.
traceroute = increasing TTL + ICMP Time Exceeded replies.
