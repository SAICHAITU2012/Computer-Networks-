Ports — Many Apps, One Machine

IP delivers to a machine; a machine runs many programs. A port (16-bit, 0–65535) identifies the process. Full address = IP : port (e.g. 192.168.1.5:52341). Multiplexing tags outgoing packets with source ports; demultiplexing delivers incoming packets to the right process by destination port.

TCP — Reliable, Ordered, Controlled

TCP's four guarantees
Reliable (data arrives or sender knows) · In-order (bytes arrive as sent) · Error-checked (bad segments retransmitted) · Flow-controlled (never drowns the receiver).
Key header fields
Src/Dst Port (16b) · Sequence (32b — byte position!) · Acknowledgment (32b — next byte expected) · Flags (SYN ACK FIN RST PSH URG) · Window (16b — receiver buffer) · Checksum.

Three-way handshake (connection setup)

Figure 2. SYN → SYN-ACK → ACK. Why random initial sequence numbers? So stale packets from an old connection can't masquerade as new ones.

Four-way close (connection teardown)

Figure 3. Each side closes independently — FIN/ACK in each direction.

Reliability — ACKs and retransmission

Sender: [seq 1–1000] [seq 1001–2000] [seq 2001–3000] Receiver: [ACK 1001] [ACK 2001] ✗ LOST Then: [ACK 3001 arrives anyway…] Receiver keeps repeating: [ACK 2001] [ACK 2001] [ACK 2001] ← 3 duplicate ACKs Sender: FAST RETRANSMIT seq 2001 immediately (no waiting for timeout)
Two retransmission triggers
1. RTO timeout — no ACK within the retransmission timeout → resend. 2. Fast retransmit — 3 duplicate ACKs → resend immediately (much faster).
Flow control — sliding window
Every ACK carries a window size = "send up to N unacknowledged bytes". Big buffer → window 65535 → pipeline freely. Full buffer → window 0 → sender pauses (zero window).

Socket Programming — Java & C++

A socket is the OS's endpoint abstraction: AF_INET (IPv4) × SOCK_STREAM (TCP) or SOCK_DGRAM (UDP).

import java.io.*; import java.net.*; try (ServerSocket server = new ServerSocket(8080)) { // bind + listen System.out.println("listening on 8080"); while (true) { Socket c = server.accept(); // blocks — handshake happens here var in = new BufferedReader( new InputStreamReader(c.getInputStream())); var out = new PrintWriter(c.getOutputStream(), true); String line = in.readLine(); out.println("Echo: " + line); c.close(); // 4-way close } }
tcp echo serverC++
int server = socket(AF_INET, SOCK_STREAM, 0); int yes = 1; setsockopt(server, SOL_SOCKET, SO_REUSEADDR, &yes, sizeof(yes)); sockaddr_in addr{AF_INET, htons(8080), {INADDR_ANY}}; bind(server, (sockaddr*)&addr, sizeof(addr)); listen(server, 5); // backlog of 5 printf("listening on 8080\n"); while (true) { int c = accept(server, nullptr, nullptr); // blocks — handshake happens here char buf[1024] = {0}; read(c, buf, sizeof(buf)); string reply = string("Echo: ") + buf; write(c, reply.c_str(), reply.size()); close(c); // 4-way close }
tcp client + udp pairJAVA
// TCP client — the handshake happens inside connect() try (Socket client = new Socket("127.0.0.1", 8080)) { var out = new PrintWriter(client.getOutputStream(), true); var in = new BufferedReader(new InputStreamReader(client.getInputStream())); out.println("Hello!"); System.out.println(in.readLine()); } // 4-way close // UDP server — no listen/accept at all try (DatagramSocket u = new DatagramSocket(9090)) { byte[] buf = new byte[1024]; DatagramPacket p = new DatagramPacket(buf, buf.length); u.receive(p); // + sender address u.send(new DatagramPacket("got it".getBytes(), 6, p.getAddress(), p.getPort())); } // UDP client try (DatagramSocket uc = new DatagramSocket()) { uc.send(new DatagramPacket("ping".getBytes(), 4, InetAddress.getByName("127.0.0.1"), 9090)); byte[] buf = new byte[1024]; DatagramPacket r = new DatagramPacket(buf, buf.length); uc.receive(r); System.out.println(new String(r.getData(), 0, r.getLength())); }
tcp client + udp pairC++
// TCP client — the handshake happens inside connect() int c = socket(AF_INET, SOCK_STREAM, 0); sockaddr_in a{AF_INET, htons(8080), {inet_addr("127.0.0.1")}}; connect(c, (sockaddr*)&a, sizeof(a)); // <- handshake write(c, "Hello!", 6); char buf[1024] = {0}; read(c, buf, sizeof(buf)); close(c); // 4-way close // UDP server — no listen/accept at all int u = socket(AF_INET, SOCK_DGRAM, 0); sockaddr_in ua{AF_INET, htons(9090), {INADDR_ANY}}; bind(u, (sockaddr*)&ua, sizeof(ua)); char buf[1024]; sockaddr_in from; socklen_t fl = sizeof(from); recvfrom(u, buf, sizeof(buf), 0, (sockaddr*)&from, &fl); // + sender addr sendto(u, "got it", 6, 0, (sockaddr*)&from, fl); // UDP client int uc = socket(AF_INET, SOCK_DGRAM, 0); sockaddr_in dst{AF_INET, htons(9090), {inet_addr("127.0.0.1")}}; sendto(uc, "ping", 4, 0, (sockaddr*)&dst, sizeof(dst)); recvfrom(uc, buf, sizeof(buf), 0, nullptr, nullptr);
Note
recv() returning 0 bytes on a TCP socket = the other side closed cleanly (this is how you detect FIN). To serve many clients at once, wrap each accepted client in a thread (or use asyncio selectors).

TCP vs UDP — the Decision Table

ConnectionConnection-oriented (handshake)Connectionless — just send

OrderingGuaranteedNot guaranteed

Exam
"A live game leaderboard updates every 100 ms — TCP or UDP?" UDP: a missed update is stale in 100 ms anyway; retransmission adds nothing but delay. "File download?" TCP — every byte must arrive, in order.
Lecture 10 — Rapid Revision Card
Port = 16-bit process ID; socket = IP:port; mux/demux by ports.
UDP: 8-B header, connectionless, no guarantees — DNS, video, VoIP, games, DHCP, QUIC.
TCP: reliable, ordered, error-checked, flow-controlled — HTTP, SSH, DBs.
Handshake: SYN → SYN-ACK → ACK (1 RTT); random ISNs defeat old-packet confusion.
Close: FIN, ACK, FIN, ACK; TIME_WAIT = 2×MSL for lost-ACK safety.
Retransmit: RTO timeout OR 3 duplicate ACKs (fast retransmit).
Window: receiver-advertised unacked byte budget; 0 = pause.
Sockets: TCP bind→listen→accept ↔ connect; UDP just bind→recvfrom/sendto.
recv() == 0 → peer closed. Well-known: 22 · 53 · 80 · 443 · 3306.

Answer Key
A1. b — 4 fields × 2 bytes.
A2. c — server's SYN+ACK.
A3. c — three dup-ACKs beat the timer.
A4. b — zero window = pause until reopened.
A5. c — listen/accept are TCP-server-only; UDP has bind→recvfrom.
A6. b — reliability of the close + duplicate expiry.
A7. Many processes per host; mux = tag outgoing with src port; demux = deliver by dst port.
A8. Prevents old-connection segments being accepted as valid data in a new connection (also raises spoofing difficulty).
A9. Each direction closes independently (half-close): FIN+ACK each way = 4 messages; open needs only agreement = 3.
A10. Timeout = wait for a full RTO; fast retransmit fires on 3 dup-ACKs, usually far sooner.
A11. Receiver advertises free buffer → bounds unacked in-flight bytes; 0 pauses sender.
A12. Peer sent FIN (closed cleanly) — close your socket / stop reading.
A14/A15. Compare with the §4 code: server thread-per-client with accept() in a loop; UDP has no accept because there is no connection — recvfrom returns the sender's address for the reply.
A16. TCP: web, file transfer, DB (every byte, in order). UDP: DNS, streaming, gaming (freshness > completeness). Mechanisms: ACK/retransmit/ordering/window vs none.
Wrap-Up — carry these into Lecture 11
TCP vs UDP
TCP = connection, reliable, ordered bytes. UDP = connectionless, 8-byte header, fast and fire-and-forget. Pick per-app, not "better".
Ports
0–1023 well-known, up to 49151 registered, rest ephemeral. Socket = IP:port; 80/443/53/22 worth memorising.
Handshake & teardown
SYN → SYN-ACK → ACK opens (seq x, x+1, y, y+1); FIN ×2 each direction closes. TIME_WAIT = 2×MSL.
Reliability engine
ACKs, retransmit (fast on 3 dup-ACKs), flow window from the receiver, congestion window from the network.
