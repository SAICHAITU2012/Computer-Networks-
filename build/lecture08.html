Distance Vector Routing

Every router: (1) knows costs to direct neighbours, (2) periodically sends its entire routing table to those neighbours, (3) updates using the Bellman-Ford rule:

dist[dest] = min( dist[dest], cost_to_neighbor + neighbor_dist[dest] )
distributed Bellman-Ford — "tell me your distances, I'll add my cost to reach you"
Convergence trace — line topology A—B—C—D (all links cost 1)
StateA's tableB's tableC's tableD's table
Initial (direct links only)B:1, C:∞, D:∞A:1, C:1, D:∞B:1, D:1, A:∞C:1, A:∞, B:∞
After round 1B:1, C:2, D:∞A:1, C:1, D:2B:1, D:1, A:2C:1, B:2, A:∞
After round 2 — convergedB:1, C:2, D:3A:1, C:1, D:2B:1, D:1, A:2C:1, B:2, A:3
Each round, information travels one more hop — good news spreads at "one hop per round" speed.

Count-to-Infinity — and the Four Fixes

Setup: A — B — C in a line. Normal state: B reaches C directly (1), A reaches C via B (2). Now the B–C link fails:

The failure (bad news travels slowly)
B detects failure → sets C = ∞ A's old table arrives: "C = 2 via me… " B thinks: via A → C = 1+2 = 3 ← WRONG (A's path went through B!) B tells A: C = 3 → A updates: 4 A tells B: 4 → B updates: 5 … …creeps up to 16 = unreachable (RIP's ∞)
Why it's absurd
A's route to C goes through B — so A can never offer B a shortcut. The routers keep "discovering" routes that route through each other: a transient routing loop where packets bounce A↔B until TTL kills them, and convergence takes minutes.
FixRuleEffect
1. Split HorizonNever advertise a route back on the interface you learned it fromA never tells B "I can reach C" — the loop never starts
2. Poison ReverseInstead of silence: advertise the route back as ∞ (16)Stronger — B pre-knows A has no independent path; instant convergence
3. Triggered UpdatesOn failure: flood "C = 16" immediately, don't wait 30 sShrinks the window where stale info circulates
4. Holddown TimerAfter poisoning, ignore claims that the route is reachable for N secondsPrevents a slow neighbour's stale table from resurrecting the dead route
Exam
The 8-mark version: "Explain count-to-infinity with a diagram and state its solutions." Draw A—B—C, show the failed link, walk the 3→4→5 numbers, then the four fixes with one-line mechanisms. This exact narrative is what graders look for.

Link State Routing — OSPF

Idea: make every router see the same complete map, then let each run Dijkstra independently — no more neighbour-gossip.

1
Discover neighbours — Hello packets (every 10 s)
Agree on hello/dead intervals, area ID, authentication → become neighbours.
2
Build a Link State Advertisement (LSA)
"I am R1. Link to R2 costs 10, link to R3 costs 5."
3
Flood LSAs to ALL routers in the area
Every router assembles the same Link State Database (LSDB) — the full topology map.
4
Run Dijkstra (SPF) on the LSDB
Each router computes shortest paths from itself → identical conclusions → consistent, loop-free tables.
5
React to change
Link fails → new LSA floods immediately → SPF re-runs. Convergence in seconds (Lecture 6's LS table explains why this beats DV).
OSPF cost formula
cost = ref_bw / iface_bw
ref = 100 Mbps default → 100M:1 · 10M:10 · 1M:100 — slower links cost more
Areas — scaling OSPF
Big networks split into areas; LSAs flood within an area only. All areas attach to Area 0 (backbone); ABRs (Area Border Routers) summarize between areas.

BGP — the Protocol Between Organisations

  • An AS (Autonomous System) = one organisation's network with a unique ASN: Google AS15169, Cloudflare AS13335, Jio AS55836, BSNL AS9829.
  • BGP (Border Gateway Protocol) = the EGP exchanging routes between ASes. It's policy-driven: business contracts decide paths as much as distance.
  • Path-vector: each advertisement carries the full AS_PATH list of networks traversed:
Google announces: 8.8.8.0/24 AS_PATH: [15169] Tata re-advertises: 8.8.8.0/24 AS_PATH: [6453, 15169] Airtel re-advertises: 8.8.8.0/24 AS_PATH: [9498, 6453, 15169] # Loop prevention: your own ASN already in the path? → discard the route.
BGP best-path order (simplified)Meaning
1. Highest LOCAL_PREFYour own policy preference (business choice)
2. Shortest AS_PATHFewer organisations crossed
3. Lowest MEDNeighbour's hint about which entry point to prefer
4. eBGP over iBGPExternal routes preferred over internal
5. Lowest IGP metric to next hopCloser exit wins ties
eBGP vs iBGP
eBGP runs between different ASes (the Internet's stitching). iBGP spreads externally-learned routes inside your own AS so all border routers agree.
BGP hijacking (real world)
Announce someone else's prefix as more specific (a /24 beats their /16 — LPM again!). 2008: Pakistan Telecom announced YouTube's /24 → worldwide YouTube traffic landed in Pakistan. Defence: RPKI cryptographic route signing.

Convergence & Routing Loops

Convergence = all routers holding consistent, correct tables. Convergence time = how long after a change before that's true.

Exam
Classic: "Two paths exist — 3 hops over 10 Mbps vs 5 hops over 1 Gbps. Which wins in RIP? In OSPF?" RIP picks 3 hops (metric = hops). OSPF picks the 1 Gbps path (costs 1+1+1+1+1=5 vs 3×10=30 — bandwidth matters, hops don't).

Count-to-∞: failed route resurrected via the neighbour who learned it from you. Fixes: split horizon · poison reverse · triggered updates · holddown.

Loops: TTL is the universal net; RIP/OSPF/BGP each prevent loops their own way.
